# v3.2 Release Notes

Release date: September 21, 2026. Research release based on frozen v3.1
(`0de8cbbef1f1842bdac54d8dba5662c78a749f06`). Previous release tags and
`v3_1_default.yaml` remain unchanged.

## Scope

v3.2 improves the default parameterization configuration and separates geometry,
distortion, numerical network inversion and validity audits. It does not claim
to solve floating-point inversion of the complete network on every mesh.
The retained v2.4 training/loss behavior is unchanged.

## Default Configuration

```text
Tutte circle, geometry scaling
-> fixed-outer-boundary six-ring scaffold
-> H1 affine: 100 updates, max_log_scale=0.08, max_shift=0.20
-> Local RQS: 500 updates, 4 cycles, hidden 32, 8 bins, bound 8
-> H2 affine: 300 updates, max_log_scale=0.16, max_shift=0.40
-> independently recorded four-metric audit
```

Only H2's amplitude and training budget change relative to v3.1. Harmonic
cycles=2, Fourier frequencies=2/3/4/5, automatically supported C0 hats=4/8/16/32,
scaffold scale=1.1/exponent=3, Adam LR=0.02/0.003, risk LR reduction/recovery,
gradient clipping=10, CUDA float64 and seed=20260906 remain unchanged.
No rollback, flip barrier, intersection penalty or added tail loss is introduced.

## Commands and Outputs

```bash
python -m pip install -e ".[test,usd]"
surface-nvp-pl --input data/input/Cow/Cow_dABF.usda --output-dir data/output/v3.2/Cow
python -m research.mesh_pl_nvp.run_v32 --input data/input/00027/Input.obj --output-dir data/output/v3.2/00027 --export-format usda
```

The new entry point uses v3.2 defaults even without YAML. The optional
`--config research/mesh_pl_nvp/v3_2_default.yaml` is equivalent; explicit CLI
arguments take precedence. Use the retained `run_harmonic_local` entry point
with `v3_1_default.yaml` for the old configuration, not the new v3.2 entry point.

`run_v32 train` saves native results without running the audit; `run_v32 audit
OUTPUT` audits them later. Repeated audits/reports require new names through
`--audit-name` and `--report-name`. By default `run_v32` does both.

- `final.obj` or `final.usda`: fixed-budget final parameterization, saved before inverse audits.
- `final.model.pt`: self-contained reference geometry, model settings, parameters and native UV.
- `reference.pt`, `snapshots/`, `training.jsonl`, `gradients.jsonl`: native-f64 records and optimizer/RNG state.
- `manifest.json`, `source.zip`: configuration, input/source hashes, versions, device and source archive.
- `audit/`: geometric, regularized/strict SD, numerical network and validity metrics.
- `report/RESULTS.md`, `report/metrics_table.json`, `report/four_metrics.png`: summaries.
- `status.json`: training outcome; `completion.json`: combined workflow outcome.

Only load trusted `.pt` files: checkpoints contain Python pickle data.
`load_checkpoint` in `run_v31_audit.py` reconstructs the saved network without
needing the original input path. The shared module retains its historical name
for compatibility; it also implements the v3.2 audit backend.

## Evaluation Contract

1. Geometric round trip samples three interior points per original triangle;
   uses independently solved barycentric coordinates and point location. Absolute
   distances and distances divided by fixed original 3D bbox diagonal `D3D` are saved.
2. Quality uses original 3D-area-weighted regularized SD, matching training:
   sum of `sigma^2 + (sigma + 1e-4)^-2`. Strict QR-based SD is reported separately.
3. Network round trip measures vertex L2 residuals divided by fixed initial
   original-UV bbox diagonal `LUV0`, with original/auxiliary/all vertex groups.
   A failure or nonfinite result remains explicit. There is no `1e-8` acceptance gate.
4. Negative-area flips, zero-area degeneracy, nonfinite faces and illegal
   unordered face-pair intersections are distinct counts, for original and extended meshes.

Every update records training SD. Snapshots are saved every 50 updates and at
stage endpoints. All snapshots receive local validity, geometry and network
audits; full intersections, export and extra geometry samples are checked at
initialization, stage endpoints and H2 100/200/300 when saved. Unchecked counts
are null, never zero. Format quantization and float32 UV-query diagnostics are separate.

Forward nonfinite/illegal states and OOM stop execution and preserve failure
records. No automatic problem-size/precision reduction is used. The edge-pair
preflight now enumerates exactly the same pairs in bounded-memory tiles instead
of allocating all upper-triangular indices at once.

## Limits and Excluded Explorations

- These are two meshes at one seed, not a universal quality/robustness guarantee.
- The global PL argument assumes a disk, fixed simple scaffold boundary and
  positive extended faces. It does not certify arbitrary floating-point execution.
- 00027's final geometric map is valid in the audits although composed network
  inversion fails. Applications requiring reliable inversion of the full network
  state remain unsupported on such cases.
- Sampling is not a continuous worst-case bound. GEOS intersections are not a
  universal exact-arithmetic certificate. Quantized exports require their own check.
- Geometry normalization does not change the training objective. The `1e-4`
  SD regularizer remains a modeling choice, not machine precision.
- H2 RQS, extended Local1000, alternating flows and numerical-protection
  variants are not the release default. H2 RQS failed its forward interval
  computation at update 261 in the 00027 exploration and is not shipped here.
- Scaffold constraints can restrict boundary motion; tail distortion remains high.
- Wall-clock comparisons from the laptop runs are not controlled performance benchmarks.

## Verification and Retention

Release checks include unit/regression tests, inverse-failure persistence,
portable checkpoint loading/re-auditing, actual Cow/00027 snapshot replay and
an installed-wheel smoke run outside the source tree. Machine-readable evidence
is in `research/mesh_pl_nvp/benchmarks/`.

Local v3.1/v3.2 baseline and adopted-run evidence are retained. Obsolete
exploration branches/worktrees and bulky discarded outputs are removed after
release verification; source backups and a cleanup inventory remain under
Git-ignored `data/archive/`. Original input meshes and old release tags are not
deleted. Large raw results/checkpoints are not uploaded to GitHub.
